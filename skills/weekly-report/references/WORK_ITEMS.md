# 工作项证据规则（本期有工作项时由中台一并加载）

工作项是「要做的事」，worklog 是「发生了什么」。本期输入另带 `work_item_evidence`，每项的来源 ID 形如 `wi:<id>`，字段含义：

| 字段 | 含义 |
|------|------|
| `bucket` | `completed` 本周完成；`in_progress` 进行中（本期有进展或排期落在本期）；`planned` 排期落在下期 |
| `in_next_period` | 排期延续到下期 |
| `kind` | `task` 一般事项；`acceptance` 计划节点的验收项（产物验证） |
| `plan` / `plan_node` | 所属计划与项目节点（计划内工作按节点归纳） |
| `progress_notes` | 本期改状态时留的备注 |
| `worklog_source_ids` | 挂在该工作项下的本期日志来源 ID |
| `overdue` | 截止已过仍未完成，只供判断 |

## 规则

1. **按工作项聚合**：`work_item_source_id` 相同的日志属于同一件事，归入同一组，该组同时引用对应的 `wi:` 来源 ID；每个 `wi:` 来源 ID 与日志一样，必须且只能出现在 `groups.source_ids` 或 `ungrouped_source_ids` 中一次。
2. **本周完成必须写**：`bucket=completed` 的工作项必须体现在本周工作总结里；`kind=acceptance` 完成时作为阶段成果表述。
3. **进行中只写有依据的进展**：只能依据其挂载日志、`progress_notes` 与描述；状态为 `todo` 且没有挂载日志的，不得写成已开展，只可作为下周待办的依据。
4. **下周待办先取日志里的后续，计划补足**：先按 SKILL.md 步骤 3，从本期日志（含 DONE 条目里写明的待办、未实施、待审批、待修订）与上一期未闭环待办中取明确的后续动作；这些不足 2~3 条时，才从 `bucket=planned` 或 `in_next_period=true` 的工作项中补足。计划排期项不得挤掉日志里明确的后续动作。待办出自某工作项下的日志时，`source_map` 同时引用该日志与对应 `wi:` 来源 ID；直接取自计划排期的，引用其 `wi:` 来源 ID。
5. **不单列延期**：`overdue` 不在甲方周报中单独写延期，只用于判断哪些事项需要列入下周待办。
6. 计划节点名、工作项标题是内部用语，按甲方口径改写，规则同 SKILL.md（去版本号、文件名，保留组件名与关键参数）。
